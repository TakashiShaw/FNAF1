## Image creation briefs

Use supplied room art as the visual reference: abandoned restaurant, grimy checkerboard floor and walls, dangling wiring, dim fluorescent light, restrained colors, subtle haze, and realistic worn materials. Avoid an unrelated cartoon style.

**Office:** First-person seated security desk, wide approximately 16:9 composition, left and right doorway openings visible, desk with fan and small monitor, wall posters and clutter, ominous but readable. Leave clear regions for independent UI controls. No clock, percentage, night label, text, cursor, border, or static overlay.

**Door/light layers:** Use the finished office as the edit reference. Preserve exact canvas size, camera position, desk, and doorway geometry. Change only the requested door, light, or visible enemy. PNG transparency for overlays; do not use JPEG for transparency. If using full-scene state variants instead, keep all unchanged pixels aligned and update this document to explain the chosen approach.

**Stage:** Fixed high-corner security-camera view, small performance stage, curtains, restaurant decor matching the supplied Dining Area. Produce a clean empty background first, then character layers for a bear with top hat/bow tie, purple rabbit, and yellow chicken. Keep their proportions and lighting consistent across scenes. No camera label or HUD.

**Cove:** Fixed security-camera view of a curtained pirate-themed alcove. Make one base composition, then matching closed, peeking, emerged, and empty states with the same curtain geometry and lighting. Foxy should be visually recognizable as a worn red fox animatronic. No overlay text.

**Characters:** Keep each character identity stable across camera, doorway, and jumpscare images. Use readable silhouettes and worn animal-machine surfaces. For camera sprites, use transparent backgrounds and enough margin around ears/limbs. Match each room angle rather than forcing a front-facing cutout into every scene.

**Title:** Dark bear animatronic face occupying the right half, empty dark space on the left for title and menu controls. No baked-in menu, logo, version number, copyright, or static; code will render live text and effects.

## Files that do not need new image generation

- Draw camera map, buttons, monitor border, stars, clock, power, usage, and win/loss text in HTML/CSS or canvas.
- Add static/scanline effects as a subtle runtime layer; keep room backgrounds clean.
- Add sound files later under `assets/audio/` and document their sources and intended triggers.
- Do not create a mask, music box, or Prize Corner background until the mixed-mechanics question in the plan is resolved.

## How to add the next image

1. Save it in the planned folder with a descriptive lowercase hyphenated filename. Keep originals when making derivatives.
2. View it at the game display size; confirm readability, alignment, and absence of unwanted baked-in UI.
3. Add an entry to `assets/asset-manifest.json` with a unique ID, repository-relative path, kind, status, dimensions, source, notes, and SHA-256 checksum. Never paste an absolute Downloads path into game code.
4. Update this inventory and mark its checklist task complete only after review.
5. When gameplay exists, reference the same path from the loader; ensure a missing asset produces a useful fallback rather than a crash.
